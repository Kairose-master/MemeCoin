02 / Attack pattern archive

Failure modes, made legible.

These are educational pattern summaries. They are not findings about any specific deployed token, and they do not certify any contract as safe or unsafe.

ACCESS CONTROLPATTERN

Unrestricted admin paths

Privileged operations lack an authorization check, or role changes can be called by anyone.

CALL ORDERPATTERN

Reentrant state changes

External control is handed off before internal accounting is updated or locked.

ACCOUNTINGPATTERN

Broken balance invariants

Unchecked arithmetic or inconsistent accounting lets balances diverge from assets.

ORACLESPATTERN

Manipulable spot prices

Single-moment prices can be distorted when protocols use them as trusted collateral values.

PROXY / STORAGEPATTERN

Unsafe delegate calls

Untrusted or mutable code targets can execute in the caller’s storage context.

INITIALIZATIONPATTERN

Repeatable initializers

Unprotected setup functions can expose ownership or configuration after deployment.

A pattern match is not proof of exploitability. Every accepted case should include a scoped environment, a minimal reproduction, impact reasoning, and reviewer notes.

04 / Review standards

Careful claims. Safe proofs.

Research quality comes from reproducibility and honest scope. The archive is not a live detection service, audit firm, or incident-response provider.

01 / Scope

Isolated environments

Demonstrations should run locally or on a test network. Do not attack live contracts, users, or infrastructure.

02 / Evidence

Reproducible reasoning

Show the relevant code, assumptions, reproduction steps, and impact. A suspicion alone is not a verdict.

03 / Disclosure

Protect users first

Do not post weaponizable details about an unpatched live vulnerability in a public issue. We do not yet offer a confidential intake channel.
