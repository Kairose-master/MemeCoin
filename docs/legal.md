# Communications and research boundaries

This is a project policy, not legal advice. Rules for token promotion, financial products, privacy, and vulnerability disclosure depend on jurisdiction and change over time. Obtain qualified advice for your circumstances before conducting a token sale, paid promotion, or bounty program.

## Public statements

- State clearly that SCAM is a meme token with no intrinsic value or promised returns and may lose all value.
- Do not imply that the project automatically detects scams, audits live contracts, certifies safety, or guarantees a bounty or listing.
- Disclose material holdings, paid endorsements, conflicts, and treasury arrangements accurately. The initial launch buy was burned; the creator may have acquired tokens separately.
- Do not make price predictions, guarantee profits, fabricate activity, coordinate wash trading, or conceal paid promotion.
- Distinguish implemented features and verified transactions from proposals.
- Describe Pump.fun coin polls as unverified community opinion only; vote counts are not findings that a project is fraudulent or safe.

## Security research

- Work only in local, testnet, or otherwise explicitly authorized environments.
- Do not exploit deployed systems or access, alter, or exfiltrate other people's data.
- Do not publish weaponizable details about an unpatched live issue through a public issue tracker.
- Never request or share private keys, seed phrases, API credentials, or unrelated personal information.

## Current project limitations

There is no live scam scanner, confidential vulnerability intake route, or active bounty program. Community polls can be brigaded and are not one-person-one-vote. Public GitHub issues are available for fictional exhibit suggestions, general research candidates, and site corrections; do not use them for confidential vulnerability disclosure.
